# ADR-041: A warehouse result names the bytes billed, the columns listing marks policy-tagged columns, an installed Codex waits out the time budget, and the CLI prints a refusal whole

- Status: Accepted; supersedes three of [ADR-034](ADR-034-warehouse-surface.md)'s consequences (the result names only what the run processed, an installed Codex keeps its own tool timeout, the columns listing marks no policy-tagged column) and amends ADR-034's `tiles warehouse rows` output and its notes
- Date: 2026-10-20

## Context

ADR-034 shipped the warehouse surface with four gaps it named or left. `getQueryResults` reports `totalBytesProcessed` and no bill, so a result named what the run processed and pointed at `bq show -j <job>`. `tiles warehouse columns` read `tables.get` but kept no `policyTags`, so a policy-tagged column looked like any other until the dry run refused a query that read it. `codex mcp add` (codex-cli 0.163.0, read from its `--help`) has no timeout flag, so an installed Codex kept its default tool timeout and could stop waiting before a 300-second query ended; only `tiles run codex` passed `tool_timeout_sec`. And every CLI failure went through `tiles_intent::one_line`, which cuts at 300 characters, so the MR manifest refusal lost the manifest path it ends with.

## Decision

- **Bytes billed from `jobs.get`.** Once the rows are read, the client calls `jobs.get` on the finished job, at `bigquery.googleapis.com` like every other call, as the new `Endpoint::Job`, and reads `statistics.query.totalBytesBilled` into `Fetched::bytes_billed`. A refused or failed `jobs.get` leaves the bill unknown and never fails a query whose rows are read. The result's sentence reads `BigQuery's dry run estimated 7.0 MB; the run processed 7.0 MB, and it billed 10.0 MB.`, or `..., and BigQuery did not say what it billed.`; `tiles warehouse rows` prints the same.
- **Policy tags from `tables.get`.** The tables API already returns `policyTags.names` on each schema field, so no second API is called. `TableInfo::policy_tagged` lists each top-level column that carries a tag, itself or in a field of its record. The listing ends such a column's line with `[policy tag]` and adds one line: the column needs BigQuery's Fine-Grained Reader role on its tag, the dry run refuses a query that reads it without that role, so leave it out. The tag's resource name is never shown.
- **The Codex install writes the timeout.** `tiles install codex` already edits Codex's `config.toml` for `default_tools_approval_mode`. When a configured source declares a chart call's longest time, the install adds a second step that sets `tool_timeout_sec` (the key codex-cli 0.163.0 reads from a server's table) in `[mcp_servers.tiles]` to that time plus 30 s, never under 120: 330 for the default budget, the value `tiles run codex` passes. It edits only that line, keeps every other byte, and stands only if the file then parses to the same config with the key set. It only lengthens the wait: a longer value stays, a shorter one is replaced in place, so a second `tiles install` or `tiles setup` changes nothing. `tiles warehouse setup`, once it makes the warehouse configured, gives an earlier Codex install the same line, and `tiles doctor` warns about a Codex tiles server whose timeout is missing or shorter, naming which.
- **A refusal prints whole.** The CLI prints a command's refusal through `tiles: ` with every character cleaned as `one_line` cleans it and no 300-character cut; only past 4,000 characters is it cut with `…`. When standard error is a terminal the text wraps at spaces to its width, later lines indented under the first's text, and a span in backticks stays whole on one line. Every path a dbt or warehouse refusal prints sits in backticks, as do the MR manifest refusal's command and dbt project directory, so a copied command or path holds no line break even when the path has a space in it. A backtick that no other closes opens no span, and the words after it wrap as usual. A word longer than a line keeps a line of its own. Off a terminal, as when Pi's extension runs `tiles warehouse columns`, it stays one line. Usage errors keep `one_line`.

## Consequences

- One more call per query, after the rows: `jobs.get` reads job statistics, which name tables and bytes, never a row. The network check's host list does not change.
- A user who set a shorter `tool_timeout_sec` for the tiles server by hand gets it raised to cover the budget; one who set a longer one keeps it until `codex mcp add` rewrites the table on a later install, which then writes Tiles' value.
- A warehouse error shown in a terminal can span several lines; scripts that read standard error get the same text on one line.
- Tests: `crates/tiles-warehouse/tests/query.rs` and `tests/surface.rs` over the replay server with `fixtures/bigquery/job-done.json` and the policy-tagged `iban` column of `table-fct-payments.json`, a refused `jobs.get` keeping the rows; `crates/tiles-cli/src/install.rs`, `setup/tests.rs`, `doctor.rs` and `tests.rs` for the timeout edit, a second setup run, the doctor warning, `tiles warehouse setup`'s reapply and the wrapped refusal, with a path holding a space and an unmatched backtick; `crates/tiles-warehouse/src/dbt/tests.rs` and `tests/replay.rs` for the backticked paths, a project path with a space among them.
