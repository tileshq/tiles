# ADR-025: Warp's window size is read as points, a card fits the visible rows, Pi takes the wrapper on the pre-cut route, and `tiles check` proves it on the laptop

- Status: Accepted; a card on the pre-cut route now shows as its block is typed, by [ADR-030](ADR-030-entrance-by-the-clock-on-every-route.md), whole from the block's first row by [ADR-044](ADR-044-precut-card-whole-from-its-first-row.md), and still counts as whole only once every row has been seen; its `/dev/tty` rule is amended by [ADR-054](ADR-054-dev-tty-only-beside-a-terminal.md): `/dev/tty` is asked only when one of stdin and stdout is a terminal
- Date: 2026-10-19
- Supersedes: [ADR-011](ADR-011-surfaces-v0-1.md)'s Pi row ("the wrapper only on sixel terminals or with `--wrapper`") and its rule that a card shows only once its whole block is on screen, outside kitty

## Context

The owner's first use of the v0.1.0 release, on an Apple silicon laptop in Warp v0.2026.10.07 (18 Oct 2026), went wrong in all three harnesses he tried through `tiles run`. In Claude Code the card came out about twice its size with the headline above the visible rows. Pi drew the card in its own green tool-result panel under a `PNG <path>` line, with a red highlight where Claude Code's was purple. OpenCode reserved the card's rows and left them blank. `tiles --version` printed 0.0.0. The causes, read from the code:

- Warp answers no `CSI 16 t`, so `tiles run` took the cell size from the window size (`TIOCGWINSZ`). Warp reports that in points, 8 by 16 a cell, and the MCP server reads `TILES_CELL_PX` as device pixels at scale 2, so it laid the card out for a 4 by 8 CSS pixel cell. The engine's 280 px minimum then took 70 columns and about 51 rows, and Warp stretched the picture over 70 real columns and 51 real rows, more than its window showed.
- `harness::draw_for` gave Pi its own image everywhere but sixel; the panel is Pi's tool-result frame and the `PNG` line was the add-on's header.
- The red bar was playbook K2: Pi's model sent `claim.tone: "bad"` for "dipped during the outage". Both paths already read the theme from `tiles_mcp::settings::theme`.
- The painter marked a card whole only when one copy ran from row 1 to the last row or started at screen row 0. OpenCode scrolls inside its own viewport under its tab bar, so a 51-row block in a message area of about 40 rows never qualified, and every token stayed blanked.
- `Cargo.toml` says 0.0.0 and the release job passed the tag only to packaging.

Warp cannot be driven on the development Mac, so none of the fixes below has been seen working in Warp; they rest on unit tests here and on `tiles check` and a re-test on the laptop.

## Decision

- **Cell size.** `detect::cell_px` takes, in order: the `CSI 16 t` reply as device pixels (kitty and Ghostty, unchanged); else the window size over rows and columns, read as points and multiplied by the session's scale. Warp reports points at every font, so in Warp the window size is always points: 8 by 16 at its default font, 10 by 20 at a 16 pt font, which no threshold could tell from pixels. In any other terminal the window size is points only when it gives a cell under 10 CSS pixels tall (`MIN_CELL_CSS_HEIGHT`), since no terminal font draws a line that short. A terminal that reports neither leaves the server's 16 by 32 default. `TILES_CELL_PX` still overrides both. The rule assumes a 2x display, as `Look::scale` does everywhere in Tiles: on a 1x display Warp's 8x16-point cell is 8x16 device pixels, and Tiles would draw it at 16x32, twice too large. `tiles doctor` names the source, and `tiles check` prints both candidates and which one won.
- **Rows fit.** On the kitty-precut route, where the terminal scales a card's visible rows to the cells they are placed on, `tiles run` passes `TILES_ROWS`, the wrapper keeps it current beside the width, and the server draws a card taller than the rows less 10 (`REPLY_ROWS`, or half the rows in a short terminal) on fewer cells, as if each cell were larger: the same pixels, the headline on the first rows, never wider than the room (`card::draw::fit_rows`). The placeholder route scrolls a whole card and gets no `TILES_ROWS`. The sixel route gets none either: a sixel is drawn at its pixel size, so a card fitted to fewer cells would spill past its block into the harness's text. A tall sixel card stays cut at the screen's edge, as before; fitting it is a follow-up that resamples the band to its cells before encoding.
- **Pi on the pre-cut route.** Pi draws its own image only on the placeholder route (kitty, Ghostty, iTerm2), where ADR-011 proved it. On the pre-cut route (Warp, WezTerm, VS Code, anything inside herdr) and on sixel, Pi gets the placeholder block and the wrapper, as Claude Code does in Warp, and the add-on renders nothing in its result, so no panel holds the card. The `PNG <path>` header is gone on every route; the path stays in the result text. `--wrapper` still forces the wrapper.
- **One theme source.** Every harness's card takes its theme from `tiles_mcp::settings::theme`: `TILES_THEME`, else the saved setting, else Obsidian (ADR-021). A red highlight is a bad claim tone (playbook K2), never a second theme. `tiles check` prints each recent card's theme and tone, so the laptop shows which it was.
- **A card is whole once every row has been seen.** The painter records, per card id, which block rows any contiguous copy has shown across paints, and marks the card whole once rows 1 to the last have all been seen, as well as by the old rule. It still draws the copy with the most rows, so a block that scrolled under a harness's own header draws its visible band. Kitty keeps ADR-017's early placement.
- **The version is the tag.** `tiles_intent::TILES_VERSION` is `TILES_VERSION` at compile time, else the workspace's 0.0.0. The release job builds with `TILES_VERSION` set to the tag without its `v`, and fails when `tiles --version` does not print it. `tiles --version`, `tiles doctor`, the MCP server's `serverInfo` and the Omni client's user agent all print it.
- **`tiles check`** prints one line per check, `pass` or `fail` first, then the fact, and exits non-zero when any fails: the version against `--tag`, or that the build carries a release version at all; the terminal and route; the graphics answer the route needs; the cell size `tiles run` would pass with its two candidates; `TILES_ROWS` on the pre-cut route and the tallest card it allows; each harness on `PATH` and who draws its card; the theme in use and where it came from; the card cache and the number of cards; for the newest five cards, their form, theme, claim tone and rows against what their terminal allowed; and, when `TILES_TRACE` names a file, whether the last session in it saw every card it made whole. The wrapper starts each session in the trace with a `tiles session <token>` line for this. Of a card it prints only its id, form, theme, tone and rows, never a title or a value from its rows (ADR-013). When stdin or stdout is not a terminal, as in `tiles check | tee check.txt`, `tiles check` and `tiles doctor` ask `/dev/tty` instead, so a piped report describes the terminal it ran in; `tiles run` still needs stdin and stdout, which the wrapper owns.

## Consequences

- A Warp on a 1x display still draws cards at twice their size; `tiles check` shows the candidates and `TILES_CELL_PX` corrects it per session.
- A card taller than the screen on the sixel route (foot, Windows Terminal) is still cut at the screen's edge, headline first, until the band is resampled to its cells.
- A card fitted to a short terminal keeps its pixels and is drawn on fewer cells, so its text looks smaller than a card of the same pixels in a tall one.
- Pi on the pre-cut route depends on its markdown putting each `[tile:` token on its own screen row, which no session on the development Mac has shown; the laptop re-test and its trace are the proof.
- A harness that shows a folded head and a folded tail of a tool result could, with the reply's copy, cover every row before the reply finishes, and the card would show a row or two early. No harness Tiles runs is known to show a tail.
- A trace written before this change has no session line, and `tiles check` says so instead of guessing.
