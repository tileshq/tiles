# ADR-028: `tiles run` keeps the model's own tools out of the card cache, `tiles cache clear` empties it, and Pi asks before an Omni-backed chart

- Status: Accepted; supersedes the consequence of [ADR-013](ADR-013-data-stays-local.md) that Omni tools run in Pi without a prompt
- Date: 2026-10-19

## Context

A security review of Tiles on 2026-10-19 rated finding S1 high. [ADR-027](ADR-027-omni-rows-stay-in-memory.md) took the Omni rows out of `<id>.call.json`, but each card's PNG still shows the values and sits in the cache, the tool result hands the model its path, Claude Code's Read tool shows a PNG to the model, and every harness gives the model a shell. A user may run Claude Code with every permission prompt turned off. Pi has no tool approvals, so with Omni configured a Pi session fetched rows unprompted. The review asked for a read deny on the cache from `tiles run claude` and the OpenCode config, `tiles cache clear`, the 300-card retention in SECURITY.md, the boundary stated plainly, and a Pi extension that asks or warns. The owner asked for every finding resolved: "We are known for our product craft and polished and smooth products + novel engineering and design principles."

## Decision

- **Claude Code gets a settings file.** `tiles run claude` writes `claude-settings.json` into the session's add-ons and passes it with `--settings`, which Claude Code 2.1.303 lists in `claude --help`. It denies `Read(//<cache>/**)` and `Bash(*<cache>*)`, with `~/` and `$HOME/` spellings when the cache is under the home directory, and states nothing else. Deny rules win over any allow and hold in every permission mode, bypass included. A Bash rule matches the command's text, so a command that spells the path another way gets past it. Tiles writes no `sandbox` entry: the cache in the sandbox's `denyRead` would be lost to every shell command of a sandboxed session, `tiles open` and `tiles cache clear` included; a user who runs the sandbox can add it themselves. Claude Code takes one `--settings <file-or-json>`, the last one given, so a `--settings` among the user's own arguments is read (a path, or JSON when the value starts with `{`), Tiles' deny rules are appended to its `permissions.deny` (none twice), the merged settings become `claude-settings.json`, and the user's own pair is dropped from the arguments. A value that cannot be read or parsed refuses the launch with one line naming it. A `claude -p` session from a scratch directory with `Read`, `Grep` and `Bash(cat *)` allowed was refused all three on a planted file in the denied cache.
- **OpenCode gets an `external_directory` deny.** OpenCode 1.19.3 asks `external_directory` with the pattern `<dir>/*` before its read, grep and glob tools touch a path outside the project and before a shell command whose arguments name one (`tool/external-directory.ts`, `tool/shell.ts`), and a pattern's `*` matches across `/`. `tiles run opencode` adds `"external_directory": {"<cache>/*": "deny"}` to `OPENCODE_CONFIG_CONTENT`; an `opencode run` session started outside the cache was refused read, `cat` and grep on the planted file. OpenCode skips the check for paths inside the directory it started in, and grep and glob ask with their search pattern rather than a path, so no rule covers a session started in the home directory. Per-tool `read` or `bash` rules would replace a user's one-word setting such as `"bash": "ask"` through OpenCode's `mergeDeep`, loosening it, so Tiles adds none.
- **Codex and Pi get no rule**, and sessions started without `tiles run` get none either. `tiles run --dry-run` prints each file a launch writes with its contents.
- **`tiles cache clear`** removes every `<id>.png`, `<id>.json`, `<id>.call.json`, entrance frame and leftover temporary write in `cards/`, prints "Removed N cards.", and leaves `run/` alone. Any other argument prints `usage: tiles cache clear` and exits 2.
- **Pi asks.** Pi 1.0.0 passes the extension context to a tool's `execute()`, with `ui.select()` and `hasUI`. Before a `tiles_chart` call whose cards fetch from Omni, the extension names the topics and offers Allow, Allow for this session, or Decline. A dismissed question declines, a session with no UI refuses, and `session_start` resets the session choice. `tiles run --allow-omni pi` passes `TILES_ALLOW_OMNI=1`, which skips the question, as `--allow-omni` pre-approves the tools elsewhere. Allow for this session mirrors the per-session allow the other harnesses offer at their tool prompt, so a user drawing a dashboard of several Omni cards answers once rather than per card, and `--allow-omni` is a launch-time choice, not a mid-session one.
- **The docs say where the line is.** SECURITY.md and `docs/omni.md` state that the harness's tool approval is the control, that a model with an unrestricted shell can read any file the user can, the card pictures included, that Pi has no tool approvals, and the 300-card retention with `tiles cache clear`.

## Consequences

- In Claude Code a shell command that spells the cache path another way, or reads it through a script, still reaches the pictures unless the user runs the sandbox with the cache in its `denyRead`. In OpenCode a session started in or above the cache, or with `TILES_CACHE_DIR` inside the project, reads it unasked, and a user's one-word `external_directory` setting is replaced by Tiles' rule for that session.
- In Pi the extension guards the Omni fetch, not the files: a Pi model's shell reads the cache unasked.
- A live MCP server keeps the rows of its own Omni cards in memory after `tiles cache clear` until its session ends.
- Tests: `claude_code_and_opencode_keep_the_model_out_of_the_cache`, `a_users_own_settings_are_merged_and_passed_once` and `omni_tools_and_omni_charts_are_pre_approved_only_on_request` in `crates/tiles-cli/src/harness.rs`; `crates/tiles-cli/tests/run.rs` for the merged `--settings` through `tiles run --dry-run`; `clear_removes_every_card_file_and_nothing_else` in `crates/tiles-mcp/src/cache.rs`; `crates/tiles-cli/tests/cache.rs` for the command, `tiles doctor` on an emptied cache and the hostile corpus; the Omni ask in `adapters/pi/index.test.ts`.
