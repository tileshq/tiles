# Architecture decision records

Each record states one decision, why it was made, and what it costs us. A changed decision takes a new record that supersedes the old one, and both stay; a correction to an old record links to the record that supersedes or amends it.

Older records cite `docs/playbook.md`, `tests/reference.rs` and `tools/`, which live in the private design repository ([ADR-038](ADR-038-open-core-split.md)); [docs/card-rules.md](../card-rules.md) lists the playbook's rules.

| [ADR-020](ADR-020-dashboards.md) | `tiles_chart` draws a dashboard (scorecards on top, charts below) in the conversation's width, corrects a model's slips with a note instead of refusing, and plays the cards in one after another from a separate half-resolution entrance |
| [ADR-021](ADR-021-obsidian-default-and-theme-switch.md) | Obsidian is the default theme; `tiles theme` and each harness's `/theme` command save a theme locally, and earlier cards switch in place in a kitty session |
| [ADR-022](ADR-022-sealed-assets-and-releases-only-channel.md) | Forms and tokens ship sealed and open only in memory; release binaries carry no source path, checked on every PR; users install from a releases-only repository; releases are signed and notarised once the Apple secrets exist |
| [ADR-023](ADR-023-open-in-a-window.md) | On macOS `tiles open <id>` shows a card as it was drawn in a window of its own, through the system's `osascript`, and every chart result names the command |
| [ADR-024](ADR-024-security-baseline-in-ci.md) | CI audits dependencies with cargo-deny and cargo-audit, fuzzes every input parser and scans every commit for secrets; Tiles sends no telemetry and collects no personal data, checked on every PR; `SECURITY.md` says how to report a vulnerability |
| [ADR-025](ADR-025-warp-cell-size-rows-and-laptop-check.md) | Warp's window size is read as points at 2x, a card on the pre-cut route fits the visible rows, Pi takes the wrapper on the pre-cut route, a card is whole once every row has been seen, the release stamps its tag as the version, and `tiles check` proves each on the laptop (its `/dev/tty` rule amended by ADR-054) |
| [ADR-026](ADR-026-formal-verification.md) | The painter's kitty motion route is a TLA+ model checked by TLC and the kitty payload encoder is proven with Kani, both beside the fuzz job in a `formal` CI job; Kani never runs on a crate that links Skia |
| [ADR-027](ADR-027-omni-rows-stay-in-memory.md) | Rows fetched from Omni never reach the disk; the session that fetched them holds them in memory and alone redraws their card in another theme; `tiles open` shows such a card as it was drawn |
| [ADR-028](ADR-028-keep-the-model-out-of-the-cache.md) | `tiles run` denies Claude Code's and OpenCode's file and shell tools the card cache; `tiles cache clear` empties it; Pi's extension asks before a chart that fetches from Omni |
| [ADR-029](ADR-029-opencode-launcher-standalone.md) | `tiles run opencode` reads `opencode --help` and passes `--standalone` to a launcher whose TUI would attach to a background service; `tiles check` and `tiles doctor` print the OpenCode version, its CLI and the version Tiles was proved on |
| [ADR-030](ADR-030-entrance-by-the-clock-on-every-route.md) | Every route plays the entrance by the clock at 50 ms a frame, Warp's included (its pre-cut entrance amended by ADR-053); a pre-cut card grows with its block on the conversation's background (superseded by ADR-044); the entrance takes the strong ease-out (450 ms), reduce motion fades it in over 150 ms, and `TILES_MOTION` sets either |
| [ADR-031](ADR-031-warehouse-sources.md) | Tiles reads warehouse tables and dbt models through `tiles-warehouse`, BigQuery first; the AI writes the `SELECT`, and Tiles dry-runs every query and refuses non-`SELECT` statements, tables outside the allowed projects and external, remote, ML and AI functions; no bytes cap; `tiles-net` holds the shared HTTP client; data sources register through `tiles_mcp::source::Source`, so `tiles-warehouse` can move to the private `tiles-pro` |
| [ADR-032](ADR-032-update-command-and-harness-versions.md) | `tiles update` installs a release through gh or a download by hand, checked against `SHA256SUMS`, unquarantined and renamed over the installed `tiles`; at most once a day `tiles run` and `tiles doctor` send one anonymous `GET` to `api.github.com` and name a newer release (`TILES_UPDATE_CHECK=off` stops it); `tiles run`, `tiles check` and `tiles doctor` name a harness version Tiles was not proved on |
| [ADR-033](ADR-033-warehouse-query-path.md) | A warehouse query names dbt models as `{{ ref('model') }}`, read from the target's build and checked with `tables.get`; each persistent routine is read with `routines.get`, and only SQL and JavaScript functions that are not remote are called; a query gets 300 s, cancelled when they end, and reads one row past its limit so a cut is reported |
| [ADR-034](ADR-034-warehouse-surface.md) | The warehouse registers through the source seam: `tiles_warehouse_models` and `tiles_warehouse_columns` let the model find models and columns, every Tiles tool asks before it runs while a warehouse is configured (`--allow-warehouse` lifts it, Pi's extension asks), a call's cards share one time budget, and a result names the build, the estimate and the job but no value (three of its consequences superseded by ADR-041) |
| [ADR-035](ADR-035-macos-package-and-tiles-setup.md) | Each release ships one universal `tiles-<tag>-macos.pkg` that installs `/usr/local/bin/tiles` and opens Terminal on `tiles setup`, which sets Tiles up for every harness on `PATH` after one question (no by default) and prints what finishes Omni and the warehouse; `install.sh` removes the quarantine flag and refuses a binary that does not run; the package ships unsigned, with a hook for Developer ID signing |
| [ADR-036](ADR-036-design-pack-seam-and-deterministic-seal.md) | A build takes the design tokens sealed in a design pack, `TILES_DESIGN_PACK=<file>`, refused unless `scripts/design-pack.sha256` pins its hash; the seal's seed comes from the SHA-256 of the plaintext, so a build from source and a build with a pack each reproduce byte for byte; `tiles-design pack` writes the pack; the themes are the tokens' list with its default; `check-release-binary.py --pack` takes its needles from the pack; `tiles --licence` names the code, design and font licences |
| [ADR-037](ADR-037-plain-theme-for-builds-from-source.md) | A build without a design pack seals a plain theme of its own, dark (the default) and light, from `assets/plain/tokens.json`, written fresh and meeting the contrast and colour-blind checks with no exemption; its goldens are `tests/golden-plain/`, the house set stays in `tests/golden/`; the rule, crisp, property and theme tests run over every theme the build carries; the `house` CI job tests the engine on design pack 1; `docs/card-rules.md` lists the rules without values and `check-docs.py` checks it in place of a missing playbook (its house exemption list superseded by ADR-042) |
| [ADR-038](ADR-038-open-core-split.md) | Tiles splits into a public `tiles` repository under FSL-1.1-ALv2, a private `tiles-design` with the house design pack, and a private paid `tiles-pro` with BigQuery and dbt; contributors sign a CLA; the official binary carries the pack sealed under its own licence and a build from source draws the plain theme; forms, fonts and the Omni connector are public; the public repository starts from one fresh root commit and keeps every ADR number (its trademark search before launch superseded by ADR-040) |
| [ADR-039](ADR-039-setup-replaces-a-stale-claude-code-server.md) | `tiles setup` replaces a user-scope Claude Code `tiles` server for another `tiles` (remove, then add) after its one question; a failed remove adds nothing and prints the commands; a server in a project's or folder's config, or with variables of the user's, is named and left; `tiles doctor` changes nothing |
| [ADR-040](ADR-040-licence-cla-and-trademark-files.md) | `LICENSE` is the canonical FSL-1.1-ALv2 text with the Inter, pstack and emil-skills notices; `LICENSE-design` covers the house pack alone, only inside an unmodified official release, and `tiles --licence` names it only for a build with a pack; contributors accept `.github/CLA.md` once through the hosted CLA Assistant; `TRADEMARKS.md` asks forks to rename; no trademark search until Tiles has paying customers; `CONTRIBUTING.md` sets the commit convention and the PR's "Built with" line is required |
| [ADR-041](ADR-041-warehouse-bill-policy-tags-codex-timeout-and-whole-refusals.md) | A warehouse result names the bytes billed, read from `jobs.get` after the rows; `tiles warehouse columns` marks a policy-tagged column from what `tables.get` returns; `tiles install codex` and `tiles setup` give Codex's tiles server a `tool_timeout_sec` that covers the time budget, only ever lengthening it; the CLI prints a refusal whole, wrapped to the terminal |
| [ADR-042](ADR-042-house-greys-meet-three-to-one.md) | The house light `cat_2`, `cat_3` and `cat_5` and dark `cat_3` and `cat_5` greys lift to stand at least 3:1 on their card in K6's order; no theme lists a colour under 3:1, and tokens that name `under_three_to_one` no longer open |
| [ADR-043](ADR-043-block-as-plain-lines-and-fence-blanking.md) | The model writes the placeholder block as plain lines, never inside a code fence (superseded by ADR-052); the wrapper blanks a code fence line on the row right above a block's first row or right below its last, and no other text (amended by ADR-057: below any of its rows) |
| [ADR-044](ADR-044-precut-card-whole-from-its-first-row.md) | On the pre-cut route the whole card shows from its block's first row over the rows the block will take, the rows not typed yet blanked; a block without room for all its rows waits until it has room or is whole (amended by ADR-053), and one that stops being typed is cut to its typed rows; a replaced picture is deleted a tick after its replacement, never in the same update (a resize too, by ADR-057); each session numbers its pictures from an id drawn from its token; a whole card in several strips goes up as one |
| [ADR-045](ADR-045-chart-call-keys-at-the-top-level.md) | The model-facing text says the chart call takes its keys at the top level and never says "intent"; a call nested under one `intent` key is read as that object with a note; a refusal names the keys Tiles left out, and one about the whole call names `arguments` |
| [ADR-046](ADR-046-companion-window-on-the-text-route.md) | On the text route on macOS `tiles run` keeps one companion window per session beside the terminal, showing each of the session's cards in place without taking focus; closing it leaves the harness running, the next card reopens it, and it closes with `tiles run`; `TILES_WINDOW=off` turns it off; `tiles setup` and `tiles doctor` say cards will not draw inline there |
| [ADR-047](ADR-047-context-greys-and-no-red-category.md) | On a line chart that names a series, the other lines take four ordered context greys per theme, each at least 3:1 on the card, 8 apart in CIEDE2000 with normal vision and each colour blindness, and without colour; no house or plain category is red, orange or magenta: light `cat_4` becomes a deep violet, dark `cat_4` the house violet, Obsidian takes the house yellow and a pale lavender for its orange and red, and plain takes a slate violet and an indigo for its orange and magenta; each replaced slot stays 10 apart from its neighbours with tritanopia, no series takes a text or axis colour, so dark `cat_2` leaves `muted`, and no category sits within 8 of a context grey but six listed house greys |
| [ADR-048](ADR-048-percent-fractions-refused.md) | A percent measure whose inline values all lie between -1 and 1 is refused in one line naming the measure column (y, or lo and hi on a dumbbell) and no row value when the title or column name reads as a rate, share or a percent above 1, and passes when they say points or write a percent of 1 or less; Tiles never multiplies, and fetched rows are out of scope |
| [ADR-049](ADR-049-worst-case-cards.md) | Every form has worst-case goldens from break-ui's catalog (a two-line title, a 30-letter word, CJK, Arabic and emoji labels, one row, no rows, values from -1,284 to 12,345,678.9; the percent forms hold -3% to 142%, and the stacked forms hold 0 to 12,345,678.9 and record their refusal of a negative value) and a rule test that their text stays on the card; a value under a tenth of the chart's compact step takes its own step, so 1,284 beside 1.28M never reads 0.00M; an axis label moves in to stay on the card; a right-to-left slope name is set apart from its value |
| [ADR-050](ADR-050-macos-system-fonts-behind-inter.md) | On macOS, PingFang SC, Geeza Pro and Apple Color Emoji set the characters Inter lacks (emoji in colour), Skia's own fallback stays off, and the goldens for them run only on a Mac whose fonts match the recorded digests; an intent may hold a zero width joiner between two emoji; a cut right-to-left label puts its ellipsis on its left |
| [ADR-051](ADR-051-worst-case-layout-follow-ups.md) | A title wraps at the card's width, as the approved gallery cards do, and `title_wrap_chars` is removed; a category label is drawn when it clears the label drawn before it by 8 px, so one long name hides only its neighbours, while a value axis keeps a fixed tick step; a lollipop value that would cross the average rule is written past it; a share above 0 or below 100 that rounds to an end reads `<1` or `>99`; a one-row lollipop draws no rule at its own mean, only an average the intent sends |
| [ADR-052](ADR-052-block-inside-a-tiles-fence-again.md) | The model writes the placeholder block inside a ```` ```tiles ```` fence again, fence lines included, since OpenCode draws a bare `[tile:]` line as a link without its brackets and the wrapper then finds no block; ADR-043's fence blanking stays (amended by ADR-057) |
| [ADR-053](ADR-053-precut-entrance-waits-for-a-still-card.md) | On the pre-cut route a moved whole card whose frame is too large to send again in a tick places its next frame sent ahead, so the entrance goes on; a card that waited for room and has an entrance to play goes up once it stops moving (whole, stalled, or a tick after a row typed in place); the trace says when a block waits for room, is held, loses its entrance and why, scrolls away or loses its copy on screen, and `tiles check` fails a session whose last placement, loss or scroll for a card is a lost copy (its held block's blanking amended by ADR-057) |
| [ADR-054](ADR-054-dev-tty-only-beside-a-terminal.md) | `tiles check` and `tiles doctor` ask `/dev/tty` only when one of stdin and stdout is a terminal, so a report piped from a shell still describes its terminal and a run with neither, an agent's, asks no terminal and says `not asked` |
| [ADR-055](ADR-055-main-skips-a-tree-its-pull-request-passed.md) | A push to main skips CI's heavy jobs when the GitHub API shows its tree is a merged pull request's head tree, the head contains main before the push, and that head's newest CI run passed every job; any doubt runs everything; `policy` runs on every push to main |
| [ADR-056](ADR-056-signed-sums-and-weekly-advisories.md) | The publish job signs `SHA256SUMS` with an ed25519 ssh key held as the secret `TILES_SIGNING_KEY`; `install.sh` pins its public half and checks the signature with macOS's own `ssh-keygen` before it trusts `SHA256SUMS`, refusing in one line when the signature is missing or wrong, for a download and a local install alike; `docs/install.md` prints the key, the hand check and `install.sh`'s SHA-256; `cargo deny check` and `cargo audit` run every week |
| [ADR-057](ADR-057-precut-fence-resize-and-waiting-rows.md) | The wrapper blanks a code fence line under any row of a block, as Pi draws while the block streams, and a row may take several blanks in one paint; on the pre-cut route a resize deletes no picture, and the next paint places each card again where its block stands, the old picture going a tick later; a block waiting for room or held has its first row blanked from the token to the end of its title, which stops at a gap of two spaces, within the width its card will be drawn at |
| [ADR-058](ADR-058-add-ons-and-fixture-cards-run-with-no-network.md) | CI's `no-network` job runs the add-ons' tests and the release-built `tiles` drawing the repo's intents through `tiles card`, `tiles theme` and `tiles mcp` in a network namespace under strace, and fails on any inet or inet6 connect or send, loopback included, any Unix socket and any DNS lookup, and refuses io_uring; it allows only kernel netlink and sends with no address, and no documented owner, since none of these paths runs the update check |
| [ADR-059](ADR-059-public-cut.md) | This repository is cut from a private repository by a script as one root commit, scanned for secrets, private names, house colours and stray binaries; `tiles-cli` builds without the warehouse; the release fetches design pack 1 from the private design repository at a pinned commit with a read-only deploy key, signs with a new key and publishes to its own releases from a `release` environment only `v*` tags reach; piped from curl, `install.sh` runs `tiles setup` from `/dev/tty` |
