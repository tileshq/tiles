# tiles run, per harness

`tiles run <pi|opencode|claude|codex>` launches the harness with Tiles loaded for that session through the harness's own options, and runs it under the wrapper only where no hook draws the card (ADR-011). `--dry-run` prints the launch; `--terminal`, `--route` and `--wrapper` override detection. With Omni configured no Tiles tool is pre-approved unless `--allow-omni` is passed (ADR-013). Claude Code and OpenCode are told to keep the model's file and shell tools out of the card cache, and Pi's extension asks before a chart that fetches from Omni (ADR-028).

## Sub-features

- `run-claude` passes `--mcp-config`, `--append-system-prompt` and, without Omni, `--allowedTools mcp__tiles__tiles_chart,mcp__tiles__tiles_theme`, then `--settings <add-ons>/claude-settings.json`, which denies `Read` and `Bash` on the cache and states nothing else, plus `--plugin-dir <mod>` in kitty and Ghostty; the model copies the block into its reply. The mod draws from the result's last `PNG:` line, and only when it names `.../cards/<id>.png` for the result's card id (`node --test adapters/claude/card.test.ts`).
- `run-codex` passes `-c mcp_servers.tiles.*` and `-c developer_instructions`; without Omni the tool runs without an approval prompt, with Omni `-c mcp_servers.tiles.default_tools_approval_mode="prompt"` makes Codex ask.
- `run-opencode` passes `OPENCODE_CONFIG_CONTENT` with the server, its tool permissions (`allow` without Omni, `ask` with it), `"external_directory": {"<cache>/*": "deny"}`, the `/theme` command and the instruction file, and sets `TILES_COLS` to the conversation's width: the terminal's less OpenCode's 42-column sidebar above 120 columns (ADR-020). It reads `opencode --help` first: a launcher that lists `--standalone` gets `--standalone` before the user's arguments, so its TUI runs a private server that loads the session's config instead of attaching to a background service, and a `--server` among them stops the launch (ADR-029).
- `run-pi` passes `-e <extension>`; the extension registers `tiles_chart` and the `<tiles>` system-prompt section; the model gets text only. On the placeholder route (kitty, Ghostty, iTerm2) it draws the saved card with pi-tui's `Image` from the result's `details`, with no header line above it; elsewhere (Warp, WezTerm, VS Code, herdr, sixel) `tiles run` wraps Pi with `TILES_DRAW=block`, the result shows nothing, and the wrapper draws the card over the block in the reply (`harness::draw_for`, `node --test adapters/pi/index.test.ts`). Before a call whose cards fetch from Omni the extension asks with Pi's `ui.select`: Allow, Allow for this session, or Decline; with no UI it refuses.
- `run-allow-omni`: `--allow-omni` pre-approves `tiles_chart`, `tiles_theme` and both Omni tools again, and passes Pi `TILES_ALLOW_OMNI=1` so its extension skips the question. The cache deny stays.
- `run-settings`: a `--settings <file-or-json>` among the user's own Claude Code arguments is merged into `claude-settings.json` (its `permissions.deny` gains Tiles' rules, none twice, every other key kept), the launch names only that file, and the user's own pair is dropped; a value that cannot be read or parsed stops the launch with one line naming it (`crates/tiles-cli/tests/run.rs`).
- `run-dry` prints the plan, with a `  file: <path> = <contents>` line for each file the launch writes, and starts nothing.
- `run-version`: before the harness starts, `tiles run` asks `<harness> --version` and, for a Pi, Claude Code or Codex whose major and minor version matches none in its row of `crates/tiles-cli/src/proved.rs` (OpenCode: the major version), prints one stderr line `Tiles was proved on <Harness> <newest proved>, and this is <installed>; if a card misdraws, run tiles check`, and prints it again after the harness exits (`the_version_line_shows_again_after_the_harness_exits`); a version it cannot read prints nothing. A dry run prints the same line on stderr with its stdout unchanged (`a_dry_run_names_an_unproved_harness_version_and_nothing_else` in `crates/tiles-cli/tests/run.rs`, ADR-032).
- `run-update-notice`: once a day a release build's `tiles run` (not `--dry-run`) asks `api.github.com` for the latest release and, when it is newer, prints `Tiles vX.Y.Z is available; run tiles update` on stderr before the harness starts and again after it exits; `TILES_UPDATE_CHECK=off` (or `0`, `false`, `no`) stops it. A development build (0.0.0) never asks, so this is covered by `crates/tiles-cli/src/update/tests.rs`, not driven.

## How to get to it (user POV)

- `tiles run claude`, then ask for a chart in words.

## Driving it with drive.sh

Preconditions:

- `scripts/doctor.sh` passes; the harness is on `PATH` and signed in. To prove a new harness release without touching the installed one, install it under a scratch prefix (`npm install --prefix <dir> @anthropic-ai/claude-code@<version>`, or `@openai/codex@<version>`) and pass `--env PATH=<dir>/node_modules/.bin:/usr/local/bin:/usr/bin:/bin`; with the full login `PATH` every drive timed out on 2026-10-19 with an empty pane. Run each from a scratch directory outside any repository, one at a time, never answering a trust, login or import prompt, and never with permission prompts turned off.

- **Plans.** `drive.sh <run> run-dry-<h> run --dry-run <h>` for each harness: the transcript names the program, every argument and the variables (`TILES_DRAW`, `TILES_COLS`, `TILES_CACHE_DIR`, `TILES_RUN=1`); Claude's ends with a `file:` line for `claude-settings.json` whose deny rules name `TILES_CACHE_DIR`, and OpenCode's config holds the `external_directory` deny for it.
- **Merged settings.** `drive.sh <run> run-dry-settings run --dry-run claude --settings '{"permissions":{"deny":["Read(//secret/**)"]},"model":"opus"}'`: the arguments hold one `--settings`, naming `claude-settings.json`, and the `file:` line's `permissions.deny` starts with the user's rule and ends with Tiles', with `model` kept. With `--settings /nowhere.json` the run prints one `tiles: cannot read --settings /nowhere.json: ...` line and exits 1.
- **Plans with Omni.** `drive.sh <run> run-omni-<h> --env TILES_OMNI_URL=https://acme.omniapp.co --env TILES_OMNI_API_KEY=planted run --dry-run <h>` (Omni counts as configured; nothing is fetched): Claude has no `--allowedTools`, Codex has `default_tools_approval_mode="prompt"`, OpenCode's config has `"ask"` for all four tools. Add `--allow-omni` before the harness: Claude's `--allowedTools` names all four tools and OpenCode's say `"allow"`.
- **Claude.** From the scratch directory: `TILES_CACHE_DIR=<out> tiles run claude -p "Chart our weekly signups: W1 120, W2 180, W3 150, W4 240, W5 310. W3 dipped because of the outage." --output-format stream-json --verbose`. The stream shows a `mcp__tiles__tiles_chart` tool use, a tool result whose first block is text with one `[tile:` line per row its `(id <id>, <cols>x<rows> cells)` names (23 on 2026-10-18, 14 on 2026-10-19 for a 36x14 card), and a final reply holding every `[tile:` line inside a ```` ```tiles ```` fence (ADR-052). Proved 2026-10-18, and 2026-10-19 with Claude Code 2.1.304; the plain lines of ADR-043 proved 2026-10-20 with 2.1.304 and 2.1.305 and 2026-10-21 with 2.1.306; the fence proved 2026-10-21 with Claude Code 2.1.306 (a 36x14 card, all 14 lines in the reply between a ```` ```tiles ```` line and a ```` ``` ```` line), and with 2.1.307, 2.1.308, 2.1.309 and 2.1.311 (a 34x14 card, the same).
- **Cache deny.** From a folder in the scratch directory, with a planted file under a cache folder: `claude -p "<Read, cat, then Grep the planted file>" --settings <the dry run's settings file> --allowedTools "Read,Grep,Bash(cat *)"` reports all three denied; `OPENCODE_CONFIG_CONTENT='{"permission":{"external_directory":{"<cache>/*":"deny"}}}' opencode run "<the same>"`, started in a sibling folder outside the cache, reports all three refused. Proved 2026-10-19 with Claude Code 2.1.303 and 2.1.304 and OpenCode 1.19.3, 2026-10-20 with Claude Code 2.1.305, 2026-10-21 with Claude Code 2.1.306 and 2.1.307, 2026-10-22 with Claude Code 2.1.308, 2026-10-23 with Claude Code 2.1.309, and 2026-10-27 with Claude Code 2.1.311.
- **Codex.** `tiles run codex exec --skip-git-repo-check "<the same request>"`: stderr shows `mcp: tiles/tiles_chart (completed)` and the reply holds the block. Proved 2026-10-18 (the model's first intent was refused and its retry drew the card), and 2026-10-23 with Codex 0.164.0 (a 36x14 card, all 14 lines in the reply inside a ```` ```tiles ```` fence).
- **OpenCode launcher.** With a stub `opencode` first on `PATH` whose `--help` prints `--standalone  Run with a private server instead of the background service`, `drive.sh <run> run-dry-launcher run --dry-run opencode -c` shows `arg: --standalone` then `arg: -c`, and `run --dry-run opencode --server http://x` prints one `tiles: OpenCode's --server attaches ...` line and exits 1. With the stub's `--version` printing `opencode v2.1.0` (2026-10-21), the dry run prints no version line, `doctor` reads `2.1.0 (proved on 2.0.32)`, and `check` passes its `opencode server:` line, since the launcher is compared by major version. With sst/opencode 1.19.3 on `PATH` the dry run has no `--standalone`. A launcher build is checked by hand ([laptop-check.md](../../../../docs/laptop-check.md#opencodes-launcher)); on one (`opencode v2.0.32`), `tiles run opencode --standalone` drew the signups card and the four-card dashboard, fitted, on 2026-10-19, where the launch without it drew none.
- **OpenCode.** `tiles run opencode mcp list` shows `✓ tiles connected`; `tiles run opencode run "<the same request>"` shows the `⚙ tiles_tiles_chart` row and the block in the reply, inside a ```` ```tiles ```` fence (ADR-052). Proved 2026-10-18; the fence proved 2026-10-21 with OpenCode 1.19.3 (all 14 lines of a 14-row card inside it). Plain lines are not enough here: in Warp, OpenCode draws a bare `[tile:` line again as a teal underlined link without its brackets, and the card goes. Warp itself is checked by hand: on 2026-10-21 on the development Mac, `tiles run opencode` in Warp drew the signups card and the four-card dashboard with the fence, and both stayed after their replies ended.
- **Pi.** From the scratch directory: `TILES_CACHE_DIR=<out> tiles run pi --no-session --mode json "<the same request>"`: the session's system message lists `tiles_chart` and holds the `<tiles>` section, the model calls `tiles_chart`, the tool result's content is text only with the card's file in `details.png`, and the reply holds every `[tile:` line inside a ```` ```tiles ```` fence (ADR-052). The default provider refused the model turn on 2026-10-18, 2026-10-21 and 2026-10-22 for an account reason ("Third-party apps now draw from your extra usage"); pass `--model <provider>/<model>` for one that answers. The plain lines of ADR-043 proved 2026-10-21 with Pi 1.2.0 (a 36x14 card) and 1.3.0 (a 34x14 card); the fence proved 2026-10-22 with Pi 1.4.0 (all 14 lines of a 34x14 card inside it, with `--model claude-bridge/claude-sonnet-5-5`). The image path is checked without a model turn: load the extension through the release's own `loadExtensions` (`dist/core/extensions/loader.js`) and call the tool's `execute` and `renderResult`. Under `TERM_PROGRAM=ghostty` it returns pi-tui's `Image`, whose lines carry kitty graphics, and with `TILES_DRAW=block` in `tool.json` it renders nothing (checked 2026-10-18 on Pi 1.0.0, 2026-10-21 on 1.2.0 and 1.3.0, and 2026-10-22 on 1.4.0). From 1.4.0 it also returns the `Image` with kitty graphics under `TERM_PROGRAM=rex`, with `TILES_DRAW=text` too.
- **Version line.** With a stub `claude` first on `PATH` that prints `2.2.0 (Claude Code)` for `--version`, `drive.sh <run> run-version run --dry-run claude` shows `Tiles was proved on Claude Code <the proved version in proved.rs>, and this is 2.2.0; if a card misdraws, run tiles check` after the plan; with a Claude Code of the proved major and minor version on `PATH` the line is absent.

## Gotchas

- The OpenCode launcher's background service keeps the configuration it started with, a tiles server from an earlier `tiles run` included, until it stops; `pkill -f opencode` stops it. Its cards then lack the session's rows and token, so `tiles check` prints them without "of N, at most M" and the wrapper leaves them blank.

- OpenCode skips `external_directory` for paths inside the folder it started in: an OpenCode cache check started in or above the cache folder reads the file, which is OpenCode's rule, not a failed deny.
- Without a terminal (`-p`, `exec`, `run`) the wrapper cannot run; `tiles run` starts the harness directly and the block stays text.
- An installed Pi extension and the run's copy would both register `tiles_chart`; the installed one stands down when `TILES_RUN=1` and `TILES_ADDONS` names another folder.
- A fresh `npm install` of an older Pi resolves its `@earendil-works/*` packages to the newest release: on 2026-10-21, 1.2.0's `^1.2.0` ranges pulled 1.3.0's pi-tui. To prove the release users installed, pin those packages to its version with `overrides` in the scratch prefix's `package.json`. From 1.3.0 Pi pins them exactly.
