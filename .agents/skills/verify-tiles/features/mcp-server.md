# The MCP server

`tiles mcp` speaks MCP over stdio: it answers `initialize` with the session instruction, lists `tiles_chart` and `tiles_theme` (and the two Omni browse tools when Omni is configured), offers the `theme` prompt ([themes](./cli-theme.md)), and answers each `tiles_chart` call with one text block and no picture, since everything in a result reaches the model provider (ADR-013). A card drawn from Omni rows leaves its values out of that text unless `TILES_OMNI_VALUES_TO_MODEL=1`. Standard output carries protocol messages only. A refused intent is a tool result with `isError` naming the key and the fix. Each card is as wide as its form and rows ask for (the `width` range in its form file), within the terminal less 8 columns, so a big number takes about 39 columns and a 12-period column chart 72. A call can draw up to 8 cards as one picture, a dashboard: the first card's intent, up to three more beside it under `row`, further rows of 1 to 4 under `rows`, and an optional `dashboard` title and note drawn once above them (ADR-020); an empty or null `row` or `rows` draws the first card alone.

## Sub-features

- `mcp-initialize` negotiates the protocol version and carries the instruction.
- `mcp-tools` lists `tiles_chart` with the generated schema (15 forms in `form.enum`) and read-only annotations; with Omni configured every tool but `tiles_theme` has `readOnlyHint: false` and `openWorldHint: true`; `tiles_theme` never reaches the network, so its `openWorldHint` is always false.
- `mcp-chart-block` under `TILES_DRAW=block` returns the placeholder block, the values and the PNG path.
- `mcp-width` sizes each card from its form's `width` range and its rows, capped by `TILES_COLS` less 8.
- `mcp-row` draws an intent with up to three more under `row` as one picture and one block, side by side, each card as wide as its chart needs and every card of a row the same height with its title, subtitle and the rest on the same lines; a scorecard among other cards is compact (no default subtitle, a short sparkline, no period labels, about half a lone card's height); when they do not fit at their forms' minimum widths it puts them on more lines in the same picture and the result text says so. A refusal inside the row names the card, such as `row[0].fields.y:`.
- `mcp-dashboard` draws rows under `rows` below the first, with the `dashboard` title and note above them as text with no card box, and the block's headline is the dashboard's title. Every scorecard goes in the top rows, and a scorecard asked for beside a chart moves up, which the text says. Each line is fitted to the widest line's width: a line or bar chart stretches, a scorecard stays at 35 columns. A row too wide for the terminal splits over the fewest lines whose widths differ least, and the text names the row and the columns it needed. A refusal names the key path, such as `rows[0][0].fields.y:` or `dashboard.title:`, and a card that is not a chart at all by its place alone, such as `rows[0][0]: not a valid chart`.
- `mcp-correct` draws an intent with a slip that shows no wrong number (a highlight naming nothing or a measure's value, an unknown unit or key, a long title, a note with nowhere to go, the keys nested under one `intent` key) and says in the result what it changed (ADR-020, ADR-045).
- `mcp-entrance` under `TILES_FRAMES=<n>` (set by `tiles run` to one card's frame count wherever the wrapper plays the entrance, in kitty and on the pre-cut route; any `n` from 2 to 60 draws) writes `<id>-anim-00.png` onward beside the card at half the card's resolution: the whole picture's entrance, with the heading and then each card entering in turn, row by row and left to right, 50 ms apart (at most 200 ms from first to last), one frame per `frame_ms` (50 ms) for as long as the entrance runs, so a dashboard's has more frames than a lone card's 10, then the settled picture at that resolution. Under `TILES_MOTION=reduce` it draws the reduced entrance instead: 4 frames of an opacity-only fade over 150 ms, every card at once (ADR-030). It puts `frames` and `frame_ms` in `<id>.json`; without `TILES_FRAMES` no frame is drawn. `<id>.json` also carries `session`, the hex token from `TILES_SESSION` (set by `tiles run` wherever the wrapper runs), or null without it.
- `mcp-chart-image` under `TILES_DRAW=image` (the default) returns no block and says the chart shows below the result.
- `mcp-no-picture` returns text only under every draw mode.
- `mcp-omni-values` leaves an Omni card's values out unless `TILES_OMNI_VALUES_TO_MODEL=1`; covered by `crates/tiles-mcp/src/server/tests.rs` and `crates/tiles-mcp/src/card/tests.rs` (no Omni on this Mac, ADR-008).
- `mcp-refusal` turns an intent that cannot draw a right card (an unknown form, pre-scaled rows, no rows) into one line, `isError: true`.
- `mcp-omni` lists `tiles_omni_topics` and `tiles_omni_fields` when Omni is configured; covered by `crates/tiles-mcp/src/server/tests.rs` against a fake source (real Omni never reaches this Mac, ADR-008).

## How to get to it (user POV)

- Harnesses start it themselves through `tiles run`. By hand: `tiles mcp`, then JSON-RPC lines on stdin.

## Gotchas

- The result carries no `structuredContent`: Claude Code hands that to the model in place of the text, which loses the block (ADR-011).
- A card's rows depend on `TILES_CELL_PX` and `TILES_COLS`; the defaults are 16x32 device pixels and 100 columns.
- A lone big number keeps the gallery's height at any width; only a scorecard in a row is compact and shorter.
